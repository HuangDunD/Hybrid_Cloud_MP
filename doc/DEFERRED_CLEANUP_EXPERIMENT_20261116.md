# Lazy 延迟清锁：服务器验证与成本对照

本轮先验证取消 Lazy 提交强制取页是否生效，再比较 Lazy、普通 2PC、Cornus 和存储通知版 Cornus 的成本。暂不推进 MIX，不改变模拟快照读，不要求 owner-side 提前安装更新。

主要结论：Lazy 提交取页已经消除，提交时间的约 97%–99% 落在提交日志同步等待上；但净吞吐收益取决于执行、锁持有和失败工作的变化。高偏斜 SmallBank 的收益在反向顺序复测中保持约 26%，其余五个条件的首轮差异在 −4.3% 到 +1.9% 之间。高偏斜 YCSB 仍主要受页面权限竞争影响，Cornus 的执行优势远大于新增提交成本。

## 版本与环境

- 新版：`042d4d8` 实现最小 home 事务状态表、延迟清锁和等待者重试；`c716eab` 修正服务器编译发现的三个成员函数的命名空间位置。实际测试版本为 `c716eab`。
- 对照：`cd7c3d4`，已经具有执行时更新回调，但 Lazy 提交仍逐条取页、补版本和清锁。对照不是本轮所有事务模型修改之前的版本。
- 开发/存储/remote 节点 `172.16.208.1`，计算节点 `.2/.3/.4`；每机 8 vCPU、约 30 GiB 内存。用户设置存储盘为 20,000 IOPS，本轮未从云 API 独立核验限额。
- 四机使用主网卡 eRDMA；27 次业务 socket 采样全部为 `rdma_state=ON`、`handshake_state=ESTABLISHED`。
- 沿用实际 `-O0 -DDEBUG` 构建，不是优化构建的峰值性能。每个 worker 一个负载 fiber，未增加同线程多事务并发。
- 日志开启；沿用 3 ms 后台刷新周期、16 条记录唤醒阈值及主动同步请求唤醒机制。数据页读取配置为 `buffered`，每表数据缓存 10,000 页，索引 15,000 页，FSM 4,000 页。
- 本地只做静态审查、整理与结果分析；编译和负载均在服务器执行。没有新增仓库测试脚本。

## 实验设计与口径

新版主矩阵为 YCSB、SmallBank，各测 `(worker/节点, θ) = (2, 0.6)、(10, 0.6)、(10, 0.95)`，四种模式，共 24 次运行。每次每节点 30 秒，`local_ratio=0.5`、`write_txn_ratio=0.8`、NO_WAIT。YCSB 的 0.8 表示每笔 10 次访问中 8 次写操作，SmallBank 则表示写事务类型比例。

旧版对照在新版矩阵全部结束后独立运行，使用同一组机器、网络与云盘。低并发两负载测 Lazy 和普通 2PC，另外两个条件测 Lazy，共 8 次。普通 2PC 作为主要逻辑未改的时间漂移参考。两版本不同时运行负载，也没有一边压测一边编译旧版。

发现高偏斜 SmallBank 明显提升后，再按旧版 → 新版顺序各运行一次相同的 30 秒条件，与首轮新版 → 旧版顺序相反。总计 11 次短验、24 次新版矩阵、8 次旧版对照、2 次针对性复测，共 45 次完成执行，均没有报告对账警告或完成计数缺口。

TPS 是三个节点各自测量窗口内 Commit TPS 的和；各节点不是一个严格同步的全局窗口。主表的执行/提交时间均除以全部已完成尝试数，包含失败尝试的影响；回滚率同时列出。高回滚时，提交摊销时间下降不等于进入提交的事务更快。

Prepare 首末差按完成多写 Prepare 的样本归一化。日志等待是跨节点同步等待调用，可能与协调者阶段重叠；取页、本地锁调用也是嵌套诊断，不能与执行时间重复相加。`fdatasync` 次数不等于设备 IOPS，客户机 `iostat` 也不等于云平台计费口径。

主矩阵为探索性单轮对照，只有高偏斜 SmallBank 做了反向顺序复测，不给统计显著性或通用优势结论。固定运行顺序与云盘波动可能影响小差距；边界附近应反向顺序复测。

## 功能验证

- 8 次基础短测：YCSB、SmallBank × 四模式，每次 5 秒。
- 2 次高冲突等待短测：Lazy、4 worker/节点、θ=0.95、WAIT_DETECT，每次 8 秒。YCSB 记录 2,710 次等待、2,352 次等待后唤醒和 84 次死锁回滚；SmallBank 记录 581 次等待、507 次等待后唤醒，其余有直接重试路径。均正常结束，无 watchdog 超时。
- 1 次 TPC-C Lazy 短测：2 worker/节点、5 秒，13,475 次尝试、93 次回滚，正常结束。保留原型业务逻辑；没有补 NewOrder 插入或改写其他历史行为。
- 运行中使用已有 bRPC 方法计数观察到 `QueryTxnStatus` 请求，证明确有远端事务状态查询。没有为此新增统计字段。

这些是正常运行、原有断言、等待活动与统计对账验证，不是完整业务数据不变量审计，也不覆盖崩溃恢复、终态回收、SQL 全入口或 MIX。

## 从对照中得到的判断

**取消提交取页并不等于消除同等数量的远程传输。** YCSB 旧版每次进入提交约有 8 次取页，但大部分可以直接本地完成。每节点 10 worker、θ=0.6 时，提交从 1.812 降到 1.603 ms/尝试，执行却从 1.166 升到 1.288 ms/尝试，回滚率从 2.91% 升到 5.39%，TPS 几乎持平。高偏斜时，总 ownership 获取次数甚至接近：旧版 4.660、新版 4.684 次/尝试；仅删除提交中的调用计数不能证明减少了这些实际权限获取。

**SmallBank 的高偏斜点有可重复的净收益。** 首轮旧版提交取页为 0.315 ms/尝试，新版为 0；执行取页也从 0.635 降到 0.473 ms/尝试。旧版提交中 `wait_release` 只占约 0.054 次/尝试，却贡献约 0.258 ms/尝试，少量昂贵的页面等待已经影响关键路径。反向复测如下，单位仍为 ms/完成尝试：

|---|---:|---:|---:|---:|
| 首轮先新版 | 18766 | 0.512 | 1.021 | 1.83% |
| 首轮后旧版 | 14829 | 0.666 | 1.287 | 1.65% |
| 复测先旧版 | 14650 | 0.673 | 1.303 | 1.67% |

两轮分别提升约 26.5% 和 26.3%。首轮新版提交日志等待反而略长于旧版（按进入提交归一化为 1.026 对 0.973 ms），所以不能把收益简单归因于新版遇到了更快的日志等待。这里支持消除提交取页能减少跨阶段干扰的解释，但没有单独隔离状态查询、清理位置与锁释放时机的各自贡献。

**高偏斜 YCSB 需要研究执行竞争。** 从 θ=0.6 到 0.95，Lazy 的 `wait_release` 平均从 0.193 增到 0.874 ms/次，Cornus 成功 remote fetch 仍约 0.09 ms/次。Lazy 本地页锁调用计时从 0.024 增到 2.055 ms/尝试，已包含在取页时间中。高偏斜时约 60% 尝试失败，提交摊销值仅 0.617 ms，但实际进入提交的均值仍为 1.545 ms；不能把前者当成持久化延迟。Cornus 此时约 6162 TPS，Lazy 约 1959 TPS，继续优化 Lazy 提交的剩余非日志工作不是主要切口。

**Prepare 首尾差和日志物理工作量都不能用固定倍数估计。** 每节点 10 worker、θ=0.6 的 YCSB 多写事务中，Cornus 首尾 YES 差为 0.755 ms，完整提交为 2.482 ms。普通 2PC 另有约 1.687 ms 决议日志等待。与此同时，Cornus 实际 `fdatasync/成功提交` 为 0.243，低于 Lazy 的 0.288；其 WAL 字节也更少。合批、日志格式和失败工作会改变物理 I/O，多个持久化参与者不自动等于更高的设备 IOPS。

未改主要路径的低并发 2PC 对照中，YCSB TPS 旧版 2158、新版 2131（约 −1.3%），SmallBank 5451 对 5452（近乎相同）。这提供了有限的漂移参考，不是所有配置的噪声上界。低并发 SmallBank Lazy 的 −4.3% 主要体现为日志等待变化，单次运行不足以认定稳定退化；Cornus-opt 在本矩阵也没有表现出对 Cornus 的一致优势。

## 解释边界与下一步

旧版在逐记录清锁之后等待最后的提交日志；新版先完成 `TxCommitOver`，再发布 COMMITTED 并通知重试。因此这次对照同时包含消除提交取页、状态查询/本地清理，以及写锁逻辑释放时机的变化。不能把全部吞吐变化归因为少了几次 FetchXPage，也不为了性能数字倒退终态发布顺序。

当前 2PC/Cornus 仍在 home 计算私有副本，Prepare 持久化写集、最终 Commit 在参与者安装业务值。其提交阶段包含必要的业务写回和通知，不能全部解释为日志等待。Lazy 的“单本地写者”也不等于只访问本地数据，它可能先把其他节点的页面取到 home。

终态表保留到进程退出，没有 GC、远端终态缓存或重启恢复。当前长时间运行的内存增长、查询代价和故障恢复均未解决。本轮不将它们扩展成完整 TIT 项目。

下一步优先在当前版本固定 I/O 和网络，改变本地性、写操作数量与写参与者分布，围绕已观察到的边界做少量反向顺序复测。先解释页面权限竞争、缓存复用、Prepare 最大完成时间和失败工作，再决定 MIX 需要什么信息。只有现有计时无法区分具体原因时，才考虑补最少的状态查询/本地清理计数。

上一轮新版 WAL 复测主要覆盖 ID 复用和写参与者数，不足以说明热点争用场景的优势是否保留。本轮在 `9cc47e5` 上补齐原偏斜条件：YCSB/SmallBank、每节点 10 worker、θ=0.6/0.95、写比例 0.8、local_ratio=0.5、NO_WAIT、RDMA、每点 30 秒，Lazy/普通 2PC/Cornus，两轮完整反向顺序，共 24 次。YCSB 是每笔计划 2 读 8 写；SmallBank 的 0.8 是写事务比例。关闭 ID 复用，YCSB `write_owner_count=0`，保留原放置规则及历史读写语义。

节点有效配置与本文件原有偏斜实验逐项比对，仅新增关闭状态的 ID 复用参数和固定写者参数；使用当前 16 MiB 日志段、50% 提前预初始化，没有改代码、刷盘策略或缓存配置。四机沿用实际 `-O0 -DDEBUG` 构建，存储盘 20,000 IOPS 是用户配置，未通过云 API 独立核验。

### 为什么偏斜与近期复用不能混为一谈

Lazy 取执行阶段 `local_manager + owner_manager + forwarded_page`；2PC/Cornus 取成功与冲突回复合计的 remote fetch。它们是不同逻辑操作，不能当作对等网络报文或实测 RTT。下表的转移日志等待嵌套在获页时间内，不能重复相加；本地页锁调用还包含无争用调用本身的开销，也不是独立于获页的另一段时间。

高偏斜下 Lazy 的获取成本和本地页面锁调用耗时上升；2PC 在固定归属节点处理记录，避免同样的跨计算节点页面权限交接。另一方面，偏斜也增加事务冲突、改变完成访问数和幸存事务集合；不能把较少的获取/尝试直接解释为页面复用改善。

ID 复用实验制造的是 worker 近期对象重访，本实验改变的是共享数据的访问频率分布。两者都可能访问热点，但多节点争写同一页时，频繁访问会伴随权限交接；页面搬来之后能否在本节点继续使用才决定净复用收益。未来模型不能只看页面访问次数，还应结合一次持有期的访问数、权限交接与排队代价、记录冲突/失败工作，以及当前提交增量。这里是对测量的解释，不是已经实现或验证的混合决策规则。

与 2026-11-16 的历史结果相比，高偏斜 YCSB 的 2PC/Cornus 优势方向保留；绝对性能和优势幅度发生变化。期间还有其他已提交修改，不能将全部跨日期差值仅归因于 WAL。旧的缓存容量、只读、local_ratio 和读写比例全矩阵仍未在新 WAL 上完整重跑。
