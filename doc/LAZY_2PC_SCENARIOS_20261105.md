# Lazy / 2PC 优势场景与成本定位（2026-11-05）

后续更新：YCSB 与 SmallBank 已统一为每 worker 独立、固定 seed 的随机状态；新版重测记录见 [随机状态统一与重测](WORKER_RNG_STUDY_20261105.md)。下文保留修复前的历史实验与适用限制。

本轮完成 40 次真实集群运行，主线结论：

- **两种执行方式都有明确优势场景。** SmallBank 只读时 Lazy 约为 Cornus 的 4.2 倍；热点写入时 Cornus 比 Lazy 高约 31%–38%，两者均完成反向顺序复验。
- **Lazy 的提交不只是一次日志 flush。** 热点下提交重新取页从约 2.7 μs/attempt 增到 236–252 μs/attempt；页面可能在执行和提交之间被转走。
- **普通 2PC 的额外决议日志有可观代价。** 不能把它与远程执行本身的访问优势混成一个吞吐数字。
- **YCSB 并发曲线暂作探索性证据。** 代码审查发现 worker 共用可变 Zipf RNG；应先修复负载生成，再将其作为正式协议对照。


本轮目标：在一小时探索内，识别当前实现中 Lazy、普通 2PC、Cornus 的优势场景，并用执行、提交、冲突和日志统计解释差异。不调整协议、日志策略或云盘配额；RDMA 固定开启。

## 实验设置与证据

- 代码提交 `f7b0f8b`；四台运行副本源码指纹 `cb2a43e8a4814fe51968c747568bea56478065ca3efac1bd2dbb95b638f9ae36`。开跑前核对源码、二进制与上一轮一致，且没有遗留实验服务。
- 三个计算节点，每节点 8 vCPU；存储与 remote_node 同机。用户报告预配置 IOPS 为 20000，本轮未通过云 API 独立读取配额。

- 针对性场景：SmallBank 每节点 8 worker，每点 45 秒。分别改变写事务比例为 0、0.2，θ 为 0.95，local_ratio 为 0.95，其余沿用扫描参数。模式顺序预先打乱，未按性能结果排序。
- `generate_log=1`，日志后台周期 3 ms、记录触发阈值 16，三个独立日志流。Cornus 指 `2pc-cornus`；未在本轮加入存储通知版本或 mix，以控制变量。
- 结果在开发服务器 `/data/workspace/Hybrid_Cloud_MP/result/protocol_study_20261105`，本地保存同名 `result` 副本。计划、每次运行的配置、节点输出、TPS 时间序列、系统采样和分析工具随结果保存。

## 指标口径

- Commit TPS 为三个节点各自测量窗口的成功提交速率之和；节点各自计时，不是严格同步的全局窗口。全窗口与去掉启动区间后的 TPS 同时保存。
- 总体执行/提交时间按所有完成尝试归一化，包含回滚。成功事务的条件均值另从四条提交路径累计执行时间和提交时间求得。高冲突场景不能只看每次尝试均值。
- 只读、单本地写、单远程写、多写路径分别计算提交均值。Lazy 的单本地写指最终只有 home 产生日志，不表示执行阶段从未跨节点。
- 所有权获取计时包括权限/页面就绪路径，可能含日志等待；remote fetch 包括服务端处理、RPC 和调用端记录拷贝，两者不是相同工作量，也不是纯网络 RTT。
- `write_commits_per_flush` 是集群成功写事务数除以集群 flush 次数，不是逐批去重后测得的事务数。多写事务可能出现在多个节点的批次中。真实日志记录数/批单独保存。
- 日志等待含参与者线程工作，可与协调者阶段重叠，不能累加为事务关键路径。`page_log` 是迁移/推送页面前的日志等待调用时间，包含已经持久化后立即返回的调用。
- 设备写 IOPS、设备写字节与 WAL 字节、fdatasync 次数分别统计，不能互相替代。日志 RPC 占用估算包含等待，不是 CPU 利用率。

## 代码审查发现及结论限制

### YCSB 的共享随机状态

`compute_server/worker/handler.cc` 创建一个 YCSB 对象并传给多个 worker。`compute_server/worker/worker.cc` 的 thread_local `ycsb_client` 只是线程独立的指针，指向的对象仍相同。`workload/ycsb/ycsb_db.h::generate_ten_keys` 调用对象内共享的 `zip_fans[target_node_id][0].next()`；`core/util/zipfan.h` 和 `core/util/fast_random.h` 会修改非原子的缓存及 RNG 状态，未见同步。

因此当前多 worker YCSB 存在数据竞争，可能影响采样及线程间相关性。本轮不改变被测代码，保留它作为当前实现的探索性观测；不能用这些结果宣称已精确隔离协议在目标 Zipf 分布下的并发扩展性。修正为每 worker 独立生成器后应重测。SmallBank 的生成器在 `run_thread` 内分别创建，不共用这一状态。

### 本地性与写比例的实际含义

- `RunYCSB` / `RunSmallBank` 用 `FastRand % 100 > local_ratio * 100` 决定是否允许随机选分区。`local_ratio=0.5` 对应约 51% 的强制本地分支，其余分支仍可能选中本节点；它不等于 50% 的记录远程访问。
- SmallBank 两表分别用不同种子洗牌布局。同一账户的 savings/checking 可能位于不同固定归属节点；从一张表的本地 key 列表选到账户，不保证另一张表也本地。提高 local_ratio 不等于消除所有多写事务。
- YCSB 的 write_ratio=0.8 在固定 10 条记录中产生 8 写 2 读；SmallBank 的同名参数是写事务类型占比。不能将两个负载视为等量写入。
- 当前代码的 Cornus 实现用于正常路径实验，不能把本轮性能验证当作完整故障恢复正确性证明。

## 原因定位与研究含义

### 1. Lazy 的明确优势：可复用的共享页面副本

只读主扫描 Lazy / Cornus 为 949660 / 222462 TPS，即 4.27 倍。两者 fdatasync 次数均为零；普通 2PC 与 Cornus 只读路径也几乎相同。因此这不是省去提交日志带来的差异。

Lazy 每次尝试仅 0.00091 次全局权限获取，Cornus 每次尝试仍有 0.996 次 remote fetch。成功事务执行分别为 15.9 / 101.2 μs。共享副本可长期复用时，把取页成本摊到大量后续访问上，比每次回 owner 取记录更有利。当前 remote-fetch 实现没有等价的只读副本/租约机制，不能将差值推广成所有远程执行系统的固有下限。

20% 写事务时两者又接近：写入使副本持续失效，Lazy 每次尝试的权限获取次数显著回升。判断访问方式不能只看读写比例，还要看权限复用与失效频率。

### 2. 远程执行的明确优势：热点下避免页面反复交接

θ=0.95、80% 写事务主扫描中，普通 2PC 比 Lazy 高 6.5% TPS，Cornus 高 31.3%。该结论使用线程独立生成器的 SmallBank，不依赖 YCSB 的共享 RNG。成功事务的执行均值为 Lazy 0.467 ms、Cornus 0.091 ms；提交均值约 1.220 / 1.222 ms。

与同为 8 worker、80% 写事务的 θ=0.6 基线对照：

| SmallBank Lazy 指标 | θ=0.6 | θ=0.95 |
|---|---:|---:|
| 成功事务执行 ms | 0.173 | 0.467 |
| 成功事务提交 ms | 1.066 | 1.220 |
| 权限获取次数/attempt | 1.193 | 1.143 |
| 权限获取 μs/次 | 125.3 | 342.3 |
| 提交重新取页 μs/attempt | 2.7 | 235.5 |
| 提交日志等待 μs/attempt | 1051.7 | 956.2 |
| 页面日志等待 μs/attempt | 2.8 | 18.8 |
| fdatasync ms/次 | 0.566 | 0.521 |

`core/dtx/dtx_exe.cc::TxCommitSingle` 在提交更新每条记录时重新调用 `FetchXPage`，统计为 `tx_commit_fetch_page_time`。执行时释放页锁之后，页面可能已经转移；提交时会再次付出获取成本。热点下这段耗时明显增加，而平均 fdatasync 没有变慢，所以不能把 Lazy 的退化主要归因于云盘同步调用变慢。

执行阶段也存在额外开销，但现有计时无法将它全部精确归因。ownership 总计跨执行/提交/回滚，而且 timer 从本地页锁操作之后开始，不能拿它与执行均值相减后断言某个未观测等待。下一步应对页面获取中“本地锁/权限等待”和“远端授予/页面到达”分别采样，并区分执行期与提交期。当前最强的直接证据是提交重新取页本身的增长，而非推测完整关键路径已经分解完毕。

### 3. 普通 2PC 的额外提交成本可以直接定位

同为 SmallBank、2 worker 的主扫描，普通 2PC 相比 Cornus 总体提交多约 0.22 ms/attempt，协调者决议日志等待约 0.23 ms/attempt；单写路径相近，多写路径差异明显。8 worker 时普通 2PC 多写提交约 2.90 ms，其中决议日志约 1.30 ms。代码中 `Tx2PCCommit` 在收齐持久化 Prepare 后同步等待决议日志，Cornus 跳过这段等待。

因此应把“远程执行方式的价值”和“额外一次决议持久化的代价”拆开。热点主扫描连普通 2PC 也能略胜 Lazy，说明足够大的访问成本差可以覆盖它；Cornus 则扩大了远程执行有利的范围。

### 4. 高本地性配置不等于没有跨节点提交

SmallBank 的 local_ratio 从 0.5 提到 0.95 后，Cornus remote fetch 从 0.913 降到 0.614 次/attempt，但多写占成功事务仍为 24.9%，与基线约 24.9% 接近。这与两张表独立随机布局一致。后续若研究共置访问的优势，应显式控制跨表账户共置，并继续核对真实参与者分布。

### 5. 下一步优先级

1. 修复 YCSB 每 worker 的随机状态，服务器实跑复验；在此之前不把 YCSB 的扩展曲线作为最终协议证据。
2. 补齐 Lazy 获取页面的阶段边界，尤其是提交时再次取页。不要将 Lazy 提交模型简化为单独一次 flush。
3. 围绕已找到的只读复用与热点交接两个场景做更细的读写比例/热点扫描，并控制跨表共置。暂不新增复杂 hybrid 调度器，也不继续扩大 RDMA 调参范围。

单点主扫描大多只有一次运行，几百分点差异不判断稳定胜负；只读/热点另有反向顺序复验。各次采用时间相关随机种子，并非逐事务相同的重放。模式执行在不同时间段，云盘时延仍可能波动。本轮没有 p99 结论，也没有故障注入。
