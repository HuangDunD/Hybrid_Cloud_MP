# 事务预热与全缓存逐页成本实验（2026-11-23）

状态：全量实验及对账完成。72 次模式运行、216 份节点输出；正式阶段数据页存储读取和缓存淘汰全部为 0。

## 问题与实验边界

检验：在页面能留在计算节点缓存、没有业务数据页存储读取的条件下，
热点页面每次申请权限的成本是否仍高于冷页，以及差额是否来自转移时等待日志持久化。
本轮不启用 MIX 决策，不增加学习模型，也不使用负载生成器的复用窗口作为模型输入。

- 三计算节点：172.16.219.138 / .139 / .140；开发与存储：172.16.208.2，bRPC eRDMA。
- 每节点 8 worker，日志开启，NO_WAIT，`parallel_page_fetch=0`。
- 每节点缓存 1GB，启用所属分区预加载；这是实验配置，仓库默认仍为 128MB。
- YCSB、SmallBank；θ=0/0.6/0.95；local_ratio=0.1/0.5/0.9；write_txn_ratio=0.8。
- Lazy、2PC、Cornus、Cornus 优化版，共 18 个 case、72 次模式运行。
- ID 复用概率为 0；不改变原数据规模和随机布局。
- 每次预热 10 秒、正式测量 30 秒。每个组合只运行一次，先看机制和跨配置一致性，
  不把它当作多次独立重复的置信区间。

不能只凭缓存配置宣称全缓存：每个节点还核验预加载候选全部载入、正式淘汰数和
`fetch_from_storage_count`（业务数据页存储读取）为零。缓存分布仍由正常权限协议演化，
不是强制每个节点预先持有全部页面副本。

## 预热实现与统计口径

实现与配置见 [benchmark_stats.md](benchmark_stats.md#事务预热与正式测量)。

1. preload 结束后，全节点同步清 `ResetBenchmarkStats` 和 `ResetPageCostStats`。
2. 同一批 worker 运行真实事务；预热到时，完成当前事务后停在循环入口。
3. 全节点到齐后排空日志，随后重置计算、存储和 worker/DTX 的测量统计。
4. 同步放行正式阶段，保留随机序列、ID 复用窗口、缓存、权限、业务修改及事务身份。
5. `PageCostStats` 保留预热历史；最终 `page_cost.tsv`、`page_hold.tsv` 标为模型历史。
   `page_cost_prewarm.tsv` 是正式运行前的累计基线，分析通过最终值减基线取得测量增量。
   `recent_ms` 是 EWMA，不参与差分。

报告 TPS、延迟和事务时间分解只包含正式阶段。设备 IOPS 取正式 TPS 的共同内部时间窗口。
页面持有表是包含预热的模型历史，对账使用“预热基线 + 正式访问次数”。

## 冷热分组与比较方法

只分析业务表 `page_id > 0`，排除文件头。按 `(请求节点, table_id, 固定归属节点)` 分层，
每层按测量期 `lazy_local + lazy_acquire` 次数排列：前 10% 为热页，后 50% 为冷页。
θ=0 中这只是观测次数分位，不代表存在人为设置的热点。
归属节点使用代码中的分区公式；不把本地比例导致的访问次数差直接当作热点。

- 权限申请成本：`lazy_acquire.total_ns / count`，包含等待和获取，不等于纯网络 RTT。
- 所有访问平均成本：`(lazy_local.total_ns + lazy_acquire.total_ns) / 总访问次数`，反映本地命中的收益。
- 转移日志等待：`page_transfer_log_wait_ns / 权限申请次数`；另报实际等待比例和每次实际等待耗时。
- 按 read/write/upgrade 分开核对，避免权限升级占比改变总体均值。
- 同时输出每个节点、固定归属分组，并检查热点阈值 1%/5%/10%/20% 的敏感性。
- 额外用预热访问次数划分冷热，再观察正式阶段成本，检查跨时间窗口的一致性。

组均值按调用数加权，不能解读为每个冷页都有同样精确的估计。输出中保留页数、调用数，
以及至少有 20 次权限申请的页数，低频页需要后续继续累积观测。
总时间减日志等待包含权限协调、排队、传输等剩余成本，不能全部称作网络开销。
read/write/upgrade 是现有获取类型；同一固定归属分组不保证当前所有者或具体 RPC 路线相同。
本轮直接解释已计时的本地页锁与日志等待部分，其余仅列为剩余成本。

YCSB 在中、高偏斜时差异明显；SmallBank 在高偏斜时明显，中等偏斜差异很小。
θ=0 的均匀负载没有稳定的冷热差异：用预热历史分组后，各配置的热/冷比都约为 1。

### 已测到的差额来自哪里

同为 local_ratio=0.1，下面两项都是除以权限申请次数的贡献：

| 负载 / θ | 分组 | 申请总时间 ms | 转移日志等待 ms | 本地页锁阶段 ms | 实际等待日志比例 |
| --- | --- | ---: | ---: | ---: | ---: |
| YCSB / 0.6 | 热 | 0.2071 | 0.02349 | 0.00060 | 3.79% |
| YCSB / 0.6 | 冷 | 0.1834 | 0.00095 | 0.00013 | 0.15% |
| YCSB / 0.95 | 热 | 0.3916 | 0.05781 | 0.12001 | 16.10% |
| YCSB / 0.95 | 冷 | 0.1607 | 0.00007 | 0.00013 | 0.03% |
| SmallBank / 0.6 | 热 | 0.1693 | 0.00456 | 0.00017 | 2.05% |
| SmallBank / 0.6 | 冷 | 0.1658 | 0.00058 | 0.00013 | 0.26% |
| SmallBank / 0.95 | 热 | 0.2572 | 0.0473 | 0.0226 | 18.13% |
| SmallBank / 0.95 | 冷 | 0.1621 | 0.0002 | 0.0001 | 0.11% |

- YCSB θ=0.6：真正发生日志等待时，热/冷单次约为 0.620/0.630 ms。
  差异主要是热页更频繁遇到等待，并非每次刷盘都更慢。
- YCSB θ=0.95：除日志等待外，本地页锁阶段的差异也明显。这里是已有
  `LockShared/LockExclusive` 阶段计时，不是元组锁等待，也不能全部解释成网络时间。
- SmallBank θ=0.95：日志等待频率和本地页锁阶段都能解释部分差额；其余部分
  保留为权限协调、排队、传输等剩余成本，本轮没有进一步强行归因。

这些是同一个实验点内的冷热对比。跨 θ 或 local_ratio 时，事务速率、日志批次和竞争
也会变化，不能只改变一个结果数字就断言某个等待因素是唯一原因。

### 单次获取更贵，不代表搬过来不划算

SmallBank θ=0.95、local_ratio=0.9，热/冷页面的一次权限申请为 0.1918/0.1493 ms，
但包含本地命中的一次访问平均为 **0.0427/0.1022 ms**。热页更多访问在本地完成，
平均访问成本反而更低。

所以后续混合决策应同时估计获取成本和本地复用收益，再考虑远程代执行及其事务级
提交增量；本轮没有更改混合策略。

### 分组稳健性与样本边界

- 用预热10秒访问次数划分冷热，再看正式30秒：YCSB θ=0.95 的热/冷比
  为 2.46/2.63/3.87，SmallBank 为 1.59/1.53/1.28（依次对应 local_ratio=0.1/0.5/0.9），
  与正式阶段自身分组一致。均匀负载则都约为 1。
- 再按请求节点、表、固定归属、read/write/upgrade 联合分层，高偏斜下热页较慢的分组：
  YCSB 为 26/27、27/27、27/27；SmallBank 为 54/54、51/54、44/54。
  因此差异不只是读写升级比例混合造成，但仍未固定当前所有者及实际 RPC 路线。
- 热点阈值改为前1%/5%/10%/20%时，高偏斜下差异仍存在；越靠近最热的部分，
  本轮观察到的获取成本越高。各阈值数值保存在 `heat_sensitivity.csv`。
- 冷页单页样本很少。例如 YCSB θ=0.95、local_ratio=0.1 的冷组共104,888次申请、
  48,312个节点/页面条目，没有条目达到20次申请；可以比较冷组均值，
  不能据此声称每个冷页的成本已估准。在线模型要保留样本数，并持续更新近期成本。
- 每个组合只跑一次，没有重复实验置信区间。本轮确认机制和方向，后续策略收益仍需独立验证。
