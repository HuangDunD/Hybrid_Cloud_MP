# 本节点页面成本选择器（原始 2PC 基线）

本实现供 SmallBank / YCSB 的 mix 模式试验使用。每个计算节点独立维护
`(table_id, page_id, read/write/upgrade) -> 近期平均获取耗时`，单位统一为毫秒。
不改业务页头，不新增预测 RPC。页面历史仍只在本节点；在线模式通过已有
Prepare/Commit 回复捎带各节点的日志成本统计。

## 热点规则与成本模型对照开关

使用配置中的 `hybrid_cost_model.enabled`，当前仍为 1：

- 显式 `enabled=0`：事务命中至少一个由 workload 标记的热点 key 就走 2PC 分支；
  没有热点 key 则走 Lazy。此分支不使用 `hybrid_skew_threshold`，不采集成本模型样本。
- `enabled=1`：保持当前成本模型及其适用范围；不适用或采样未就绪时，仍使用原有
  热点占比阈值回退。当前 `include_2pc_execution_cost=0`，因此不叠加 2PC 执行访问估计。

注意：源码此前实际使用“热点 key 占比 >= hybrid_skew_threshold”，不是“任意一个热点”。
上述显式 0 的行为按 2026-10-27 的对照要求调整；缺少 `enabled` 字段的旧配置仍保持
原占比规则。热点集合仍由原 workload 的 HOT_KEY_TOP_N/热点标记定义，此开关不改变
热点定义，也不改变只读/单写提交优化或纯 Lazy、纯 2PC 的协议。

对照时只切换 enabled，保持负载、HOT_KEY_TOP_N 等参数一致。两组需分别新建实验计划，
防止已保存计划中的配置指纹继续使用旧值；修改后的代码和配置需同步到远程计算节点。
原始结果中的 `hybrid_cost_enabled` / `hybrid_cost_active`、stats.log 中的 active 列可
用于确认选择器是否启用；0 组的成本模型决策计数和采样计数应为零。

## 选择规则

仅在首轮写集合分布到至少两个固定归属节点时应用成本模型：

```
默认简化模型：预计 Lazy 页面获取成本（逐页求和的 m*T） > 额外提交成本
    => 选择 2PC；否则选择 Lazy
```

2026-10-27 按实验要求，配置 `include_2pc_execution_cost=0` 暂停计入整个 2PC
执行访问估计。固定参数下阈值为 `2*r+2*f`；在线模式保留原有提交成本估计
（同等节点成本时退化为该公式）。页面历史和在线日志/RPC 参数继续更新，
这里的“冻结”是停止使用执行成本项，不是冻结时间序列。

- 固定模式中，`r` 为计算节点间基础 RPC RTT；`f` 为一次日志持久化确认等待，
  包括批处理、存储通信和落盘，两者从配置读取。在线模式改用实际采样值，
  并按各参与者的两轮最长预测等待计算提交差额，详见下文。
- 同一事务按表/页去重，有写访问时使用写权限需求。本地权限已可用且没有
  pending/granting/evicting 或冲突页锁时，预计额外获取成本为零。
- 有 S 权限但需要写时，使用 upgrade 历史；其他需要获取/等待的访问使用 read/write 历史。
- 简化模型中，固定归属节点就在本节点的页也只计入 Lazy 预测一侧，不在右侧抵消；
  右侧整个执行访问预测为零。实际执行仍使用原页面权限和持久化机制。
- 若将 `include_2pc_execution_cost` 恢复为 1，则启用此前的扩展模型：本节点归属页
  的预测成本计入两边、相互抵消；归属远端的访问按逐记录 GetDataItem RPC 次数累计。
  采用本节点近期成功 RPC 的读/写分类平均耗时，包含参与者内部的页面获取，
  不重复叠加参与者获取时间。尚无 RPC 样本时以配置 `r` 估计。
- 只读、单写参与者、TPCC、SQL、含 insert/delete 的请求保留原选择/执行方式。
  多阶段请求只使用第一轮已知访问集合，后续不会切换协议；本模型面向访问集合
  已知的 SmallBank/YCSB 路径，不声称预测任意动态 SQL 的完整读写集合。

决策位于首个 TxExe 内 key->Rid 定位完成后、业务页获取之前，复用定位结果。
每笔事务只决定一次。权限快照只是预测，不代替执行时正常的权限与锁检查。

## 统计方式

- 对需要获取/等待的业务数据页，从本地页锁申请之前计时，至页面可用结束。
  包含本地排队、远端协调、必要的日志等待、页面到达。索引/元信息页不采样。
- Lazy 分支、参与者服务、提交/解锁中经过相同获取接口的访问都可更新历史。
  直接可用的本地页不向迁移耗时历史写入近零样本。
- 按 `ewma_alpha` 平滑更新；页历史缺失或过期时使用本节点同类型近期平均，
  同类型也无有效样本时使用 `initial_page_ms`。
- 统计表分为 16 个分片，每片 FIFO 淘汰；总条目数不超过 `max_entries`
  （容量向下取 16 的倍数）。淘汰业务页不立即删除成本历史。
- 历史只在进程内，不持久化。所有计时使用单调时钟；旧 ownership_transfer
  计数和计时口径保留，不能与新样本数视为同一指标。

## 配置与对照

`config/compute_node_config.json` 已设置 `local_compute_node.cornus_prepare_commit=0`，
以未优化 2PC 作为所有模式的共同基线。成本选择器在顶层配置：

```json
"hybrid_cost_model": {
  "enabled": 1,
  "include_2pc_execution_cost": 0,
  "rpc_rtt_ms": 0.1,
  "log_wait_ms": 5.0,
  "initial_page_ms": 1.0,
  "ewma_alpha": 0.2,
  "history_ttl_ms": 10000,
  "max_entries": 65536,
  "include_remote_fetch": 1,
  "online_sampling": 1,
  "online_update_interval_ms": 1000,
  "online_ewma_alpha": 0.2,
  "online_min_samples": 100,
  "online_history_ttl_ms": 10000,
  "online_freeze_after_ms": 0
}
```

配置 r/f 是固定模式的试跑值，**不是本次在目标集群标定的结果**。
`online_sampling=0` 时，固定提交差额为 10.2 ms；设为 1 时，在线决策不使用
该固定提交阈值，样本不足/过期会退回热点策略。GetDataItem 缺少执行耗时样本时，
仍以配置 `rpc_rtt_ms` 作为其执行成本的初值。

- `enabled=1`：mix 多写参与者使用成本选择器。
- `include_2pc_execution_cost=0`：暂时排除整个 2PC 执行访问估计（当前配置）；
  设为 1 恢复扩展模型。旧配置缺少此字段时保持之前的行为，缺省值为 1。
- `online_sampling=1`：在成本选择器内启用在线提交成本；缺省或 0 则保持此前的固定模型。
- `online_freeze_after_ms=0` 持续更新；正数（如 10000）用于采样后冻结的对照。
  这是各条有效时间序列独立的采样期限，不是全节点同步预热屏障。
- 显式 `enabled=0`：使用“至少一个热点 key”的对照规则，且不采样成本；
  缺少整个配置块或 enabled 字段时，保留历史热点比例阈值规则。
- `include_remote_fetch` 仅在扩展模型下控制远端 GetDataItem 估计；它单独设为 0
  不会去掉本节点归属页的抵消项。整个执行项的开关以上一项为准。
- 模型启用时要求 `generate_log=1`、`cornus_prepare_commit=0`、
  `parallel_page_fetch=0`。不符合时 mix SmallBank/YCSB 启动明确报错，避免错误套用公式。
- 纯 Lazy / 纯 2PC 不运行选择器，也不新增成本采样。切换 Cornus 优化进行其他实验前，
  先关闭这个仅针对原始 2PC 的模型。

正常通过 test_multi_node.py 部署时会复制配置。需新建实验计划/结果目录，
不要续跑原源码与配置指纹不同的旧计划；已有结果未修改。
如果自行跳过部署，须保证目标二进制及配置已经同步。

## 看结果

每节点 result.txt 新增 `hybrid_cost_*` 字段。新生成的 stats.log 包含：

- `hybrid_cost_settings`：各节点实际是否启用、r、f、提交差额、是否计远端访问。
  这里的 r/f/delta 列明确标为 configured/fixed，是固定模式配置值。
  `include_2pc_execution_cost=0` 时 `predicted_2pc_access_ms` 应为 0；该值表示选择器
  排除了此项，不代表实际执行没有耗时。老结果缺少新开关字段时显示 N/A。
- `hybrid_online_costs`：在线模型实际是否启用、r/f 是否可用、最近估计、有效样本数、
  发布次数、冷启动/过期回退次数、实际决策使用的平均提交差额、冻结配置。
  `r_ready` 是汇总报告状态；某次事务还要求其每个写参与者都有有效统计。
- `hybrid_online_log_phases`：Commit/Prepare/Backup 的样本数及有效 f；分类不足时
  f 用节点全部三类日志的近期平均。result.txt 另含逐目的节点的 r/f 及可用标志。
- `hybrid_cost_model`：符合模型条件的决策数、选择两条路径的次数、回退数、
  页样本数、页历史命中/回退次数、两边预测访问成本、单次决策耗时。

预测访问成本及决策耗时均按模型决策数加权平均，不含回退事务；2PC 访问预测值
不含提交差额；在线模式实际使用的差额见 `used_commit_delta_ms`，它是按决策数
加权的均值。决策计数包含之后执行回滚的事务，不等于提交计数。
采样自身的开销不全包含在 decision_overhead_ms，应通过开关对照测量整体影响。

## 在线日志成本（2026-10-26）

### 采样边界

- f 从标记的结束日志进入节点队列开始，到成功的存储 LogWrite 返回、发布持久化
  LSN 的时刻结束。逐事务结束标记采样，包含批次排队、序列化、存储 RPC、存储端
  排队和 fdatasync 确认；不除以批次事务数，不包含业务页面获取及行锁等待。
- 只标记普通 Commit、旧 Prepare、coordinator Backup，Abort/页面迁移等待不混入
  提交 f。提交日志标记包含 Lazy/本地单写/远端单写/多写参与者的正常提交，
  因而冷启动不必等待大量多写事务才有 f。仅新增观测，原有持久化等待和锁语义不变。
- r 在成功的旧 Prepare/Commit 回复完成回调中采集，使用 brpc 已完成的 RPC 耗时，
  减去回复里的参与者 handler 单调时钟耗时（包括日志等待、页面/锁处理及统计快照）。
  结果是网络、序列化及 handler 之外调度的近似耗时，不是纯物理网络 RTT。
  Commit 样本包含单写远端，用于积累该目的节点的控制通信历史。
- 不用 GetDataItem 总耗时充当控制 r，不用存储 LogWrite RPC 充当 r；后者已经在 f
  中。延迟 Join 不增加 RPC 样本。失败/缺失或版本不符的遥测不作为有效数据；负差值
  丢弃并计数，不截断成零。此次没有改变原有失败处理、重试或恢复语义。
- 回复只传 duration/age，不比较不同节点的时钟时间戳；新 protobuf 字段都是附加的，
  不改变 YES、事务身份或 Commit 类型。旧节点没有遥测时相关事务退回热点策略。
- 入队时间和阶段标签只在 LogRecord 内存对象中，不进入日志序列化，不改变 WAL
  格式、业务页、页面 LSN 或恢复信息。

### 更新和选择

每个节点维护一个日志总平均及 Commit/Prepare/Backup 分类平均；协调者另维护每个
目的节点的控制 r 和该节点回复携带的 f。窗口至少经过 1000 ms 且包含 100 个样本时，
发布窗口算术平均，再按 `0.8*旧估计 + 0.2*窗口平均` 更新。查询或新样本会触发
到期发布，无额外后台线程。样本不足时可累计到 TTL，但不会无限累计陈旧样本。

10 秒内没有有效更新则退回热点策略。分类 f 不足时用本节点近期日志总平均；
本节点 f 或任一写参与者的 r/f 不足时，整次决策回退，不用配置 f 填补缺口。
如果热点策略始终没有产生相关目的节点的成功控制 RPC，该目的节点会持续处于
冷启动状态；本版不主动增加探测流量或强制改变事务模式来收集样本。

对协调者 c、写参与者集合 W：

```
Prepare = max(w in W) [r(c,w) + f_prepare(w)]
Commit  = max(w in W) [r(c,w) + f_commit(w)]
Delta   = max(0, Prepare + f_backup(c) + Commit - f_commit(c))
简化模型：预测 Lazy 页面成本 > Delta 时选择 2PC
扩展模型：预测 Lazy 页面成本 > 预测 2PC 访问成本 + Delta 时选择 2PC
```

减去的是 Lazy 本来就要做的一次本地提交日志等待。旧实现向本地参与者也发 RPC，
因此 c 在 W 中时仍采集实际自调用 r。各阶段 f 和各节点 r 相同，公式还原为
`2r+2f`。取各参与者平均耗时的最大值仍是近似，不是整个并行阶段尾延迟的精确期望。

冻结选项从每条序列开始采样计时，在超过期限且获得有效估计后冻结；已冻结值
不会因 TTL 过期。尚无样本的目的节点继续冷启动，已有值不阻止新目的节点建立
估计。各节点不保证同时冻结。统计计数继续累计，便于比较在线更新与冻结方案。

### 适用边界

当前默认配置启用在线采样，仍仅在 mix 的 SmallBank/YCSB 成本选择器中生效；
纯 Lazy、纯 2PC、Cornus 路径不启用它。只读和单写不由本模型重新选择协议。
Prepare/Commit 的日志等待、coordinator Backup、全部 Commit RPC 的同步等待均保留。
没有启用 AsyncCommit2pc，没有额外 RPC、远程部署、长实验或修改既有实验结果。

在线更新只能改善提交成本估计；未增加行锁等待/回滚概率/重试链模型，也未统一
各模式的锁等待策略。建议首先以 `lock_mode=0` 对比 enabled=0、固定成本、在线成本，
并观察 cold_or_stale_fallback、实际 used_commit_delta_ms 与 2PC 选择比例。
