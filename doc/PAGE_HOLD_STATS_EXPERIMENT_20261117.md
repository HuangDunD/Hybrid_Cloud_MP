# 页面连续持有期间的访问统计

当前统计只观测普通取页，不修改 MIX 决策或 ID 复用生成器。目标是验证：不读取 `id_reuse_prob` 或 worker 的近期 ID 窗口，仅观察内核的页面访问与权限变化，能否识别实验产生的复用程度。

## 统计口径

每个计算节点、每个数据页面单独记录一次连续持有期间服务的访问次数。

- 在 `FetchSPage/FetchXPage` 共用的 Lazy 取页实现成功返回前计一次，包括本地命中和从远端取得权限后的首次访问。直接调用相同 Lazy 取页实现的访问也使用这一入口。
- 本轮排除已有 `Commit` 阶段标记的取页；提交时绕过 Fetch 的可选本地清锁也不计。开始、执行、回滚及未标记阶段的普通取页仍计入；不按 SQL、业务 ID 或事务类型分类。等待循环不计。
- 普通释放本地 latch 不结束持有期间。只有本地失去页面权限，或者淘汰页面并释放权限时，才结束本次持有。
- S→X 升级若没有失去本地权限，仍属于同一次连续持有；升级中实际让出权限，则结束旧周期，重新取得权限后开始新周期。
- Shared 与 Exclusive 共用这个连续持有口径，因此这里的“持有”不专指排他所有权。
- 基准结束时不强制关闭仍持有的页面。`completed` 是已结束周期，`active` 是尚未结束周期的已观察访问量。`all_observed` 包含未结束周期，不能当成完整生命周期均值。

访问次数是页面接口层的服务次数，不是不同事务数、不同 ID 数或业务复用概率。同一事务多次取页、检查旧记录锁后的重新取页都可能增加计数。`completed_reused_holds` 只表示次数大于 1 的已结束周期，不表示发生了跨事务复用。后续代价模型必须保持这一口径，不能把这些数直接当成业务概率。

## 最小实现

2026-11-23：持有统计已集中到 `core/compute_node/page_cost_stats.h` 的 `PageCostStats`，
与逐页 Lazy/远程访问成本共用节点内的表/页数组。`LRLocalPageLock` 不再保存 HoldStats，
只在原有权限结束位置通知统计对象。Fetch 入口直接更新统一统计；字段、持有边界和输出口径不变。
具体成本字段见 [逐页成本与复用](benchmark_stats.md#逐页成本与复用2026-11-23)。

以下为 2026-11-17 的初始实现记录：直接扩展现有 `LRLocalPageLock`，不新建按页哈希表，不写入数据页面、日志或持久化格式。锁表对象在缓冲页淘汰后仍保留，因此历史可跨多次取得/失去权限累积，直到计算进程结束。

- `compute_server/lazyrelease_server.cc`：在既有 S/X 取页成功统计旁调用 `RecordFetchAccess`，排除提交阶段。
- `core/LPLM/local_LR_page_lock.h`：`HoldStats` 五个 `uint64_t`（每个现有锁对象增加 40 字节）。`RecordFetchAccess` 在调用者仍持有页面 latch 时，用现有 mutex 保护计数；普通加锁方法和可选本地访问方法不再自行加一。`EndHoldNoLock` 在原有六处权限变为 NONE 的路径上汇总并清零当前周期。没有新增锁状态转换。没有发生过符合口径的 Fetch 的周期不纳入统计。
- `compute_server/run.cc`：工作线程完成并经过现有节点结束屏障后，读取各数据页锁表的快照，输出明细及节点汇总。仅输出表 ID 小于 10000 的数据页，与现有 Lazy 取页统计一致；不输出索引/FSM 页。
- `tools/benchmark/report.py`：`stats.log` 增加 `page_hold_stats`，分别展示已结束、仍持有、所有已观察周期的访问均值。旧统计、`summary_human.txt` 保留。
- `test_multi_node.py`：回收每个节点的 `page_hold.tsv`，重跑前清理对应旧产物。2PC/Cornus 不产生 Lazy 持有统计；不需要新增配置项。

`page_hold.tsv` 每行是该节点的 `(table_id, page_id)`：

| 字段 | 含义 |
|---|---|
| completed_holds | 已结束的持有次数 |
| completed_accesses | 上述持有期间的访问总数 |
| completed_reused_holds | 上述持有期间访问次数大于 1 的次数 |
| max_completed_accesses | 已结束持有期间的最大访问次数 |
| active_accesses | 当前未结束持有期间的访问次数，0 表示没有已采样的开放周期 |

每节点对账关系为：

```
completed_accesses + active_accesses
  = 原有 Lazy 非 Commit 阶段、各路径的成功取页次数之和
```

`cached_visits` 已从新输出删除。集群均值使用总访问数除以总周期数，不平均各页面或各节点的平均值。不同节点持有同一页面是不同观测对象。

### 结果与结论

四台服务器构建通过，4 次真实短测、12 次正式运行全部完成。48 份节点配置/结果核对通过，其中 42 份 Lazy 逐页文件的合计、开放周期数、最大值及与既有取页统计的对账全部通过；另外 6 份 Cornus 节点结果没有产生 Lazy 持有文件或字段。无报告 WARNING，完成尝试计数一致。

源码指纹：`879f2fa74c7161d1cbf03ade35c6eea1b3bc464e86cf33bd1a09642de7c8e91c`。实验当时，本地、开发目录与四台部署的四个变更代码/脚本文件哈希一致。实验结束后开发目录的 ID 复用配置恢复关闭、窗口 64，YCSB 固定写归属恢复 0；实验服务已全部退出。部署目录保留最后一次实验的运行配置，下一次由主脚本正常覆盖。

| 负载 | ID 复用概率 | 已结束周期平均访问数 | 仍持有周期当前平均访问数 | 跨节点获页路径次数/尝试 |
|---|---:|---:|---:|---:|
| YCSB | 0 | 2.344 | 2.134 | 5.991 |

这里跨节点获页路径复用现有 `local_manager + owner_manager + forwarded_page + wait_release` 计数，汇总全部阶段，再除以含回滚的完成尝试数；不是网络报文数或精确 RTT 数，不含存储取页和权限升级。

- **持有期间的访问次数能反映这组实验的复用强弱。** 两轮 YCSB 的已结束周期均值分别为 2.344/2.343、4.171/4.179、11.768/11.776；SmallBank 分别为 2.791/2.792、4.331/4.333、10.414/10.405。反转顺序后结果接近。
- **信号在逐页层面也存在。** 对每个有已结束周期的节点页面，先计算其 `completed_accesses / completed_holds`，再取这些页面均值的中位数：YCSB 约 2.25→4.17→15.00；SmallBank 约 2.40→3.72→9.67。这里每个节点页面等权，与上表按周期加权的均值不同。
- **仍持有的周期不能遗漏。** 高复用点有 12.51%（YCSB）、10.63%（SmallBank）的已观察访问发生在尚未结束的周期。它们已经服务很多次访问，且未来还可能继续；因此保留 active，而不在结束时假造一次权限释放。
- **增长不是本地可选清理占比大幅变化造成的。** 成功本地非阻塞访问约占总页面服务次数的 32.25%–32.46%，各概率接近。统计仍按统一页面接口口径计入这些访问，不去猜测业务语义。
- 与持有访问数上升同时，跨节点获页次数明显减少。YCSB 回滚率约 2.13%→2.05%→1.55%；SmallBank 约 0.01%→0.01%→0.02%，没有出现靠大量提前回滚制造访问下降的现象。

这支持把“本节点页面在一次连续持有期间可服务多少次访问”作为后续模型的观测量。当前只证明它在这些固定负载参数下能区分复用强弱，没有证明累积历史能预测热点迁移后的未来，也不等于仅凭该数就能决定转移或远程执行；传输、等待、提交与缓存占用的成本仍需合并考虑。本轮没有实现预测器或更改混合选择规则。
