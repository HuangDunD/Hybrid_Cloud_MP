## 三、缺陷闭环记录

**D-1（已闭环，`6670297`+`5d820da`+`007803d`）**：原发 `r2c-20260923-c5-anchor-early-001`——早锚点 X 取页连环 stuck（45.5s grant 死等＋latch 残留）。修复后早锚点 PASS（d1-fix-verify-001 → matrix-early-003）。

**D-2（本轮发现并闭环，`213c5fc`）**：矩阵收尾 HEAD 复跑早锚点首发两连败——
- `matrix-early-001`：compute_C SIGABRT，`RecoverAddHolder` S 分支 `assert(lock != EXCLUSIVE_LOCKED)`。根因：Phase 2 汇报是各节点扫描时刻快照，与汇报者事务释放、paged 在线域锁活动三方并发；首个 newest 汇报即 ClearIRLock 提前放行在线域，迟到汇报与在线 X 授权在权威侧组合出违反互斥的 holder 集合。
- `matrix-early-002`：层1修复（延迟清 IR）后不再崩溃，但 page 32 权威 holders=[2] 幽灵 S（本地 LPLM 无记录）挡 B 的 X 排队，B↔C 互卡 45s/轮至 wall budget。根因："释放先到（stale 无操作）、汇报后到（重建）"竞态；`5d820da` 收窄 L16 没收范围后失去 ForfeitAllHolders 兜底掩盖。
- 修复三处（详见 33.8）：①清 IR 延迟到 Phase 2 barrier 收齐后统一 finalize；②GPLM stale-unlock tombstone 拒绝过时汇报重建；③S/X 释放 RPC 失败重定向到新 manager 重试。CTest 7/7，early-003/mid-001 PASS。
- 触发面定性：早锚点冷缓存（事务必走远程取页、幸存者对受影响页持有真实锁快照）必踩；晚锚点热缓存未触发（late-006 过）。global 模式窗口全拒、无并发汇报交错，不触发。
